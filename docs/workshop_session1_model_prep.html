The problem we're solving

Bank regulators score every bank they supervise on CAMELS — Capital adequacy, Asset quality, Management, Earnings, Liquidity, Sensitivity to market risk — a 1 (strongest) to 5 (weakest) rating built from exams and ratio analysis. A weak rating is an early warning that a bank is heading toward trouble.

Here's the catch: real CAMELS ratings are confidential supervisory information. They're shared only with a bank's own management and its regulator — on purpose, so a public downgrade doesn't trigger the very bank run the exam was trying to prevent. No dataset anywhere contains real, regulator-issued CAMELS labels for individual banks.

So what are we actually predicting?

Exactly what the peer-reviewed bank-failure-prediction literature predicts: a transparent, documented proxy — not the confidential real thing. We build (1) a rule-based composite score from public financial ratios, and (2) a real "did this bank fail?" flag from FDIC's public failure history, and we use the second to check that the first is actually tracking real distress. Every prediction this model makes gets that caveat attached: decision-support and early-warning, never a replacement for a regulator's judgment.

The dataset

We're using one dataset today: the FDIC BankFind Suite API — free, public, no login required for a session like this. It's real U.S. bank regulatory financial data, quarterly, going back to 1992, covering every FDIC-insured institution.

Pull data from the FDIC API

In [2]:

Live pull — institutions, financials, failures

One small helper (fdic_get) wraps the shared request logic; then we call all three endpoints for the most recent full-year quarter. LIVE_PULL_OK tells Cell 3 whether it needs to step in.

FDIC_BASE = "https://banks.data.fdic.gov/api"

def fdic_get(endpoint, params, timeout=30):
    resp = requests.get(f"{FDIC_BASE}/{endpoint}", params=params, timeout=timeout)
    resp.raise_for_status()
    payload = resp.json()
    return pd.DataFrame([row["data"] for row in payload.get("data", [])])

FIELDS = ",".join([
    "CERT", "REPDTE", "ASSET", "EQ", "RBCT1J", "RBC1RWAJ",
    "NPERFV", "LNATRES", "NETINC", "NIMY", "ROA", "ROE", "EEFFR", "LNLSNET", "DEP",
])

LIVE_PULL_OK = False
try:
    # No ACTIVE:1 filter, and a limit well above one quarter's ~4,700 banks:
    # a bank that later failed is, by definition, not "active" today - filtering
    # to ACTIVE:1 (or truncating the pull) would silently drop it before we ever
    # get to check whether it failed. See Cell 4 for the other half of this fix.
    institutions = fdic_get("institutions", {
        "fields": "CERT,NAME,STALP,CHARTER,ASSET,BKCLASS", "limit": 10000, "format": "json"})
    financials = fdic_get("financials", {"filters": "REPDTE:20231231",
        "fields": FIELDS, "limit": 5000, "format": "json"})
    failures = fdic_get("failures", {"fields": "CERT,NAME,FAILDATE,CITYST,SAVR,COST",
        "limit": 5000, "format": "json"})
    LIVE_PULL_OK = all(len(df) > 0 for df in [institutions, financials, failures])
except Exception as e:
    print(f"Live FDIC pull unavailable here ({type(e).__name__}). Using the fallback in the next cell.")

print("Live pull succeeded:", LIVE_PULL_OK)

Fallback sample

In [3]:

Only runs if Cell 2 couldn't reach the API

Same column names, realistic distributions, and a built-in relationship between weak fundamentals and failure — so every cell below behaves identically either way. If Cell 2 succeeded, this cell does nothing.

if not LIVE_PULL_OK:
    n_banks = 1500
    cert = np.arange(100000, 100000 + n_banks)

    institutions = pd.DataFrame({
        "CERT": cert,
        "NAME": [f"Synthetic Bank {i}" for i in range(n_banks)],
        "STALP": rng.choice(["NY", "CA", "TX", "IL", "OH", "GA", "FL", "PA"], n_banks),
        "CHARTER": rng.choice(["N", "SM", "SB", "NM"], n_banks),
        "ASSET": rng.lognormal(mean=12, sigma=1.5, size=n_banks).round(0),
        "BKCLASS": rng.choice(["N", "SM", "SB", "NM"], n_banks),
    })

    tier1 = rng.normal(11, 3, n_banks).clip(2, 25)
    npl_ratio = rng.gamma(1.5, 0.8, n_banks).clip(0, 15)
    provision_ratio = (npl_ratio * rng.uniform(0.3, 0.6, n_banks)).clip(0, 8)
    roa = rng.normal(1.0, 0.6, n_banks) - 0.15 * (npl_ratio - npl_ratio.mean())
    efficiency_ratio = rng.normal(62, 12, n_banks).clip(30, 110)
    ldr = rng.normal(80, 15, n_banks).clip(30, 130)
    liquid_asset_ratio = rng.normal(18, 8, n_banks).clip(2, 50)

    financials = pd.DataFrame({
        "CERT": cert, "REPDTE": "20231231", "ASSET": institutions["ASSET"],
        "EQ": (institutions["ASSET"] * (tier1 / 100) * rng.uniform(0.8, 1.1, n_banks)).round(0),
        "RBCT1J": tier1.round(2), "RBC1RWAJ": (tier1 * rng.uniform(0.9, 1.1, n_banks)).round(2),
        "NPERFV": npl_ratio.round(2), "LNATRES": provision_ratio.round(2),
        "NETINC": (roa / 100 * institutions["ASSET"]).round(0),
        "NIMY": rng.normal(3.3, 0.7, n_banks).clip(0.5, 6).round(2),
        "ROA": roa.round(2), "ROE": (roa * rng.uniform(8, 12, n_banks)).round(2),
        "EEFFR": efficiency_ratio.round(2),
        "LNLSNET": (institutions["ASSET"] * rng.uniform(0.5, 0.8, n_banks)).round(0),
        "DEP": (institutions["ASSET"] * rng.uniform(0.75, 0.92, n_banks)).round(0),
        "LDR": ldr.round(2), "LIQ_RATIO": liquid_asset_ratio.round(2),
    })

    distress = (
        -0.35 * (tier1 - tier1.mean()) / tier1.std()
        + 0.30 * (npl_ratio - npl_ratio.mean()) / npl_ratio.std()
        - 0.20 * (roa - roa.mean()) / roa.std()
        + 0.15 * (efficiency_ratio - efficiency_ratio.mean()) / efficiency_ratio.std()
        - 0.10 * (liquid_asset_ratio - liquid_asset_ratio.mean()) / liquid_asset_ratio.std()
        + rng.normal(0, 0.5, n_banks)
    )
    fail_threshold = np.quantile(distress, 0.97)
    failed_mask = distress >= fail_threshold

    failures = pd.DataFrame({
        "CERT": cert[failed_mask], "NAME": institutions.loc[failed_mask, "NAME"].values,
        "FAILDATE": "2024-06-30", "CITYST": institutions.loc[failed_mask, "STALP"].values,
        "SAVR": "SYN", "COST": rng.uniform(1e5, 5e7, failed_mask.sum()).round(0),
    })
    print(f"Synthetic sample ready: {n_banks} banks, {len(failures)} flagged failed "
          f"({len(failures)/n_banks:.1%}).")

Build the CAMEL ratios

In [4]:

Feature engineering — one ratio per component

Merge financials (the base population — every bank that filed a Call Report this quarter) with institutions left-joined on for identity metadata, then compute one ratio for each CAMEL letter. The merge order matters: joining the other way round (institutions as the base) would silently drop any bank not in that pull — including, worst of all, banks that have since failed. Note also the honest caveat on efficiency_ratio: Management is the one component with no clean financial-statement equivalent, so we approximate it — a standard, literature-backed substitution, not a claim it's equivalent to real supervisory judgment.

df = financials.merge(institutions, on="CERT", how="left", suffixes=("", "_inst"))
df["failed"] = df["CERT"].isin(failures["CERT"]).astype(int)

camel = pd.DataFrame({"CERT": df["CERT"], "NAME": df["NAME"], "STALP": df["STALP"], "ASSET": df["ASSET"]})

# RBC1RWAJ, not RBCT1J: RBCT1J is a DOLLAR AMOUNT (Tier 1 capital in
# thousands), not a percentage - confirmed against the live API. .clip
# guards against a handful of raw records with implausible outlier values.
camel["tier1_ratio"] = df["RBC1RWAJ"].clip(lower=0, upper=50)   # C - Capital adequacy
camel["npl_ratio"] = df["NPERFV"]                        # A - Asset quality
camel["efficiency_ratio"] = df["EEFFR"]                  # M - Management (proxy only, see note above)
camel["roa"] = df["ROA"]                                 # E - Earnings
# loan_deposit_ratio, not a "liquid assets" field: the FDIC fields we pull
# never include one, so that column would be 100% missing on live data.
camel["loan_deposit_ratio"] = df["LNLSNET"] / df["DEP"] * 100   # L - Liquidity
camel["loan_concentration"] = df["LNLSNET"] / df["ASSET"] * 100  # S - Sensitivity proxy

camel["failed"] = df["failed"]
camel.head()
05

Composite proxy rating

In [5]:

Combine six ratios into one 1–5 rating

Each ratio is z-scored in its "healthier" direction, averaged, then bucketed into quintiles — 1 is healthiest, 5 is weakest, matching CAMELS' own convention. This becomes our regression/classification target since no ground-truth rating exists to train against.

def healthy_z(series, higher_is_better=True):
    z = (series - series.mean()) / series.std()
    return z if higher_is_better else -z

camel["z_capital"] = healthy_z(camel["tier1_ratio"], True)
camel["z_asset_quality"] = healthy_z(camel["npl_ratio"], False)
camel["z_management"] = healthy_z(camel["efficiency_ratio"], False)
camel["z_earnings"] = healthy_z(camel["roa"], True)
camel["z_liquidity"] = healthy_z(camel["loan_deposit_ratio"], False)  # lower loan/deposit = more liquid
camel["z_sensitivity"] = healthy_z(camel["loan_concentration"], False)

component_cols = ["z_capital", "z_asset_quality", "z_management",
                   "z_earnings", "z_liquidity", "z_sensitivity"]
camel["composite_z"] = camel[component_cols].mean(axis=1)

camel["composite_score_0_100"] = (
    (camel["composite_z"] - camel["composite_z"].min())
    / (camel["composite_z"].max() - camel["composite_z"].min()) * 100
).round(1)

camel["proxy_rating_1_5"] = pd.qcut(camel["composite_z"], q=5, labels=[5, 4, 3, 2, 1]).astype(int)

camel[["NAME", "composite_score_0_100", "proxy_rating_1_5", "failed"]] \
    .sort_values("composite_score_0_100").head(10)

Six component distributions, then the one chart that matters most: does the composite score actually separate failed banks from healthy ones?

fig, axes = plt.subplots(2, 3, figsize=(15, 8))

for ax, (col, label) in zip(axes.ravel(), comp_display.items()):

    ax.hist(finite_vals, bins=30, color="#2b6cb0", alpha=0.85)

Baseline model

In [7]:

Train a classifier on the real failure label

We train on failed — the real, independent label — not the composite score we just built by hand. Failures are rare, so class_weight="balanced" matters: watch precision/recall/F1 on the failed row, not overall accuracy, which would look great even from a model that never catches a real failure.

feature_cols = ["tier1_ratio", "npl_ratio", "efficiency_ratio", "roa",
                "loan_deposit_ratio", "loan_concentration"]
X = camel[feature_cols].replace([np.inf, -np.inf], np.nan)  # a bank with 0 deposits -> inf ratio
X = X.fillna(X.median())
y = camel["failed"]

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=RNG_SEED, stratify=y
)

model = RandomForestClassifier(
    n_estimators=300, max_depth=6, class_weight="balanced", random_state=RNG_SEED
)
model.fit(X_train, y_train)

y_pred = model.predict(X_test)
print(classification_report(y_test, y_pred, target_names=["healthy", "failed"]))
print("Confusion matrix:\n", confusion_matrix(y_test, y_pred))
imbalanceon the synthetic sample, failures are ~3% of banks. On live FDIC data for one quarter, real failures are far rarer — often just a handful out of ~4,700 banks — so a 0.00 precision/recall on the "failed" row is expected here, not a broken model: no classifier can learn a pattern from that few positive examples. That's exactly the class-imbalance problem this step exists to make visible, and exactly why a real deployment pools failures across many quarters instead of one.

XAI — explain the model

In [8]:

SHAP: why did the model say what it said?

A global bar chart ranks which ratios matter most across every bank; the waterfall plot then explains one specific bank's prediction — exactly the "show your work" the client-facing agent will need later. If explanation[:, :, 1] errors on your SHAP version, print explanation.shape and index accordingly — the shape varies slightly by version.

explainer = shap.TreeExplainer(model)
explanation = explainer(X_test)   # unified SHAP Explanation object

# Global: which ratios drive the "failed" prediction most, across all test banks?
shap.summary_plot(explanation[:, :, 1], X_test, plot_type="bar", show=True)

# Local: why did the model say this about ONE specific bank?
bank_i = 0
shap.plots.waterfall(explanation[bank_i, :, 1], max_display=6)
print("This waterfall shows exactly which ratios pushed this bank's failure-risk score up or down.")

A quick fairness check, by state

Does the model's predicted risk skew by state in a way the actual failure rate doesn't? A real fairness audit goes deeper (charter type, asset size, more groups) — this is the shape of the check, not the full version.

camel_test = camel.loc[X_test.index].copy()
camel_test["predicted_failed"] = y_pred

fairness_check = camel_test.groupby("STALP").agg(
    n_banks=("CERT", "count"),
    actual_failure_rate=("failed", "mean"),
    predicted_failure_rate=("predicted_failed", "mean"),
).round(3)
print(fairness_check)

Model card — write down what this model is and isn't

Every model that goes near a real decision needs one of these: what it predicts, what it was trained on, and the caveats that keep it honest.

model_card = {
