Project story

Module 1 — Data Science + Financial Data Analysis

Core foundation

Concept

  • Understand the business problem before writing code.
  • Perform EDA on financial and risk data.
  • Detect missing values, outliers, class imbalance, and time drift.

Project implementation

  • We use FDIC institutional and financial data to build CAMEL-style ratios.
  • Features such as tier1_ratio, npl_ratio, roa, and loan_deposit_ratio are engineered into a coherent financial-risk structure.
  • We also compare healthy and failed banks using a proxy label: failure within N quarters.

Best teaching takeaway

A good AI project starts from the data domain. In this case, the domain is financial health, not generic tabular ML.

Module 2 — Deep Neural Networks and AI Foundations

Why we did not force a deep network

Concept

  • Perceptrons, feedforward networks, optimization, activation functions.
  • Use ANNs when patterns are nonlinear and data is large enough.
  • Study adversarial examples and robustness.

Project implementation

  • The main CAMEL data is structured tabular data, so tree-based models are often more interpretable and more dependable.
  • The project currently uses a tuned HistGradientBoostingClassifier and a baseline random forest.
  • There is still room to add an MLP benchmark and adversarial robustness checks on bank ratios.

Future extension

Add a small neural-network baseline to compare predictive performance, then study how small perturbations to ratios affect the final risk class.

Module 3 — NLP + Financial Text AI

Security and language layer

Concept

  • Text representation, embeddings, NER, sentiment, and prompt safety.
  • PII protection and prompt injection defense.

Project implementation

  • The main model is numeric, not NLP-heavy.
  • However, the chat agent accepts free-form user messages, so we must protect the system from prompt injection and sanitize any financial data.
  • The chat workflow is structured so the LLM never creates a risk decision itself; it only interprets the ML tool output.

Real-world lesson

Even a numeric model can still be exposed through an LLM. The real security risk is at the boundary between natural language and the model tool call.

Module 4 — Generative AI, LLMs & RLHF

Explanation generation

Concept

  • Transformers and instruct-tuned LLMs generate context-rich explanations.
  • Alignment and guardrails keep the AI on-task.

Project implementation

  • The project uses Azure OpenAI to turn model output into plain-language answers.
  • The LLM explains the risk result using SHAP contributions instead of inventing a rating.
  • The system prompt is designed to prevent hallucinated regulatory statements or unsupported judgments.

Teaching angle

This is a perfect example of using LLMs not for prediction itself, but for explanation and conversation around the prediction.

Module 5 — RAG, LangChain & AI Agents

Tool-calling agent

Concept

  • Use tools, not free-form reasoning, to access real functions.
  • Keep the action space small and controlled.

Project implementation

  • The score_bank tool is allow-listed and returns probability, tier, SHAP contributions, LIME output, and counterfactuals.
  • The chat agent in src/camel_sentinel/chat/agent.py calls the tool, receives the result, and then produces a natural-language answer.
  • The backend exposes this as a service layer, making the system extensible beyond a notebook demo.

Why it matters

Real AI systems should rely on tools and verification, not raw model memory. This reduces hallucination and unsafe action-taking.

Module 6 — Explainable & Responsible AI

Trust, fairness, and governance

Concept

  • Explain why the model makes a decision.
  • Audit fairness, risk, bias, and model governance.

Project implementation

  • SHAP is used to explain feature contributions.
  • LIME provides a local surrogate view.
  • Counterfactual explanations show what change would move a bank from risky to lower risk.
  • Responsible AI checks include subgroup audit for size and region.

Real lesson

A model without explanation is hard to trust in regulated environments. In banking and healthcare, interpretability is not optional.

Module 7 — Federated & Privacy-Preserving ML

Privacy-first learning

Concept

  • Train across decentralized data owners without sharing raw data.
  • Use FedAvg, clipping, and noisy updates for privacy-aware coordination.

Project implementation

  • The project simulates multiple data silos by state and runs a federated learning loop.
  • Updates are clipped and perturbed before aggregation to make the training more privacy-aware.
  • This teaches the idea even if the final system is still centralized for an MVP.

Why this matters

This matches real institutional constraints: institutions rarely share sensitive raw financial records with each other.

Module 8 — Multimodal AI

Next-level intelligent interfaces

Concept

  • Combine text, image, audio, and structured data in one system.
  • Production interfaces increasingly mix modalities.

Project implementation

  • The project already includes voice input and speech synthesis.
  • Combine that with uploaded documents, bank statements, or financial reports for richer risk-assessment workflows.
  • Future versions could process PDF annual reports alongside ratio-based scoring.

Extension idea

Add OCR and document summarization for annual reports, compliance notices, or audit summaries.

Module 9 — MLOps, Deployment & Production Systems

Turn research into a product

Concept

  • Model versioning, monitoring, CI/CD, retraining, and deployment pipelines.
  • Production-grade systems need guardrails, reproducibility, and observability.

Project implementation

  • The backend and Streamlit UI provide a working service layer and interaction surface.
  • The model is serialized and loaded repeatedly, which is the right first step toward real MLOps.
  • The next move is to add cloud deployment, automated tests, model registry, tracking, and drift monitoring.

Production-ready checklist

Add authentication, monitoring, retraining jobs, versioned datasets, alerts, and model governance before exposing the service to real users.
